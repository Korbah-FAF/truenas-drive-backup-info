TrueNAS Drive Backup

Privacy policy

This policy describes a personal backup application operated by its owner for their own Google account.

Information accessed and purpose

The application requests Google's drive.file permission to create, list, read, update and remove its own backup files and folders in Google Drive. It processes file identifiers, names, sizes, modification times and repository contents to perform backups, integrity checks, retention maintenance and recovery. Access is limited to files created or explicitly opened with this application.

Selected source files are read on the owner's private server. Restic encrypts backup contents and file names before uploading them. Google Drive stores the encrypted repository and can process its storage and activity metadata under Google's own policies.

The application does not request Gmail, Google Photos, contacts or calendar permissions. It does not use Google user data for advertising, profiling, sale or AI model training.

Storage and security

Google OAuth credentials and refresh tokens are stored in a protected configuration on the owner's server. The backup encryption password is stored separately from the cloud repository. Recovery requires that password. The owner controls access to the server and its backup interface.

Encrypted backup data is stored in the owner's Google Drive. Local logs and backup indexes can contain source paths, timestamps and operational information. They remain under the owner's control.

Sharing and providers

Backup data is transferred to Google Drive to provide the storage requested by the owner. The application does not intentionally publish backups or share them with other users. Sharing permissions on Google Drive are controlled by the account owner.

This informational website has no forms, application cookies or added analytics. If hosted on GitHub Pages, GitHub processes visitor connection information, including IP addresses, under the GitHub Privacy Statement. Google handles account authorisation and cloud storage under its Privacy Policy.

Use of information received from Google APIs will adhere to the Google API Services User Data Policy, including its Limited Use requirements.

Retention, deletion and revoking access

Backup versions are retained according to the owner's configured retention settings. The owner can delete backup versions through the backup software and remove the cloud repository through Google Drive. Removing old versions may require repository maintenance to reclaim stored data; Drive trash may also retain deleted files until it is emptied.

The owner can revoke the application's access through Google Account settings. Revocation stops future authorised access; it does not by itself delete existing encrypted backups. The owner can also remove the application's locally stored credentials and backup settings.

Questions and changes

Contact the operator through the support email shown on the application's Google consent screen. This policy will be updated if the application's data practices change.
